# IT System Cost Overview

무형자산상각비 · 전산용역비 Executive Dashboard.
화면의 모든 수치는 `data/current.xlsx`를 **페이지를 열 때마다 브라우저에서 읽어 계산**합니다. 코드에는 금액·항목·기간이 들어 있지 않습니다.

```
index.html
css/dashboard.css
js/app.js                     화면 렌더링 · 상태 · 이벤트
js/excelParser.js             Sheet/Header 탐색, Alias Mapping, 값 검증 (보정 없음)
js/depreciationCalculator.js  월 상각액 · 연도별 상각비
js/contractTimeline.js        계약 주기 · 연장 가정(갱신마다 3~5% 인상) · 연도 금액(월할 안분) · 월별 지출(지출 월)
js/charts.js                  연도별 상각비 Column Chart (SVG)
js/vendor/xlsx.core.min.js    SheetJS CE 0.20.3 (Apache-2.0, cdn.sheetjs.com 공식 배포본)
data/current.xlsx             ← 관리자가 교체하는 파일
tests/verify.mjs              계산 Logic 검증
```

## 1. 실행 방법

브라우저 보안 정책상 `index.html`을 더블클릭(`file://`)하면 Excel을 읽을 수 없습니다. 웹서버를 통해 여세요.

```bash
python -m http.server 8765
```

브라우저에서 `http://localhost:8765` 접속. (Node가 있다면 `npx serve .` 도 가능)

- 첫 화면: **연간 IT System 비용 합계 카드** + **IT System 비용 합계(누적) · 무형자산상각비 연도별 추이** 그래프 (올해부터 표시). 모든 금액은 `백만원` 단위, 소수점 아래 1자리로 표기.
- 그래프의 연도 막대(또는 카드의 '상세 내역 보기')를 누르면 그 연도의 **상세 내역**(무형자산 상세 · 전산용역 계약 현황 · DATA CHECK)이 열립니다.
- 공유 링크: `…/index.html?year=2027` (요약만), `…/index.html?year=2027&detail=1` (상세 내역까지 열린 상태)
- 기본 연도는 오늘이 속한 연도이며, Excel 데이터 범위 밖이면 가장 가까운 연도로 맞춥니다.

## 2. Excel 교체 방법

1. 새 Excel 파일명을 `current.xlsx`로 바꿉니다.
2. `data/current.xlsx`를 덮어씁니다.
3. 페이지를 새로고침합니다. (서버 캐시가 있어도 매 로드 시 재검증 요청을 보냅니다)

상단 **Data Updated**에는 Excel 파일 내부의 마지막 저장 시각이 표시됩니다(없으면 서버 반영 시각).

## 3. Excel 필수 Column

Sheet명과 Header 위치는 고정이 아닙니다. Sheet명에 아래 키워드가 들어가면 찾고, 상단 30행 안에서 Header 행을 찾습니다.

| 구분 | Sheet명 키워드 | 필수 Column (별칭 허용) | 선택 Column |
|---|---|---|---|
| 무형자산 | `감가상각` · `무형자산` · `상각` | 항목명(자산명·System·시스템명) / 총 금액(총금액·취득금액·계약금액) / 기간(감가상각 기간·상각기간·사용기간) | 매월 감가상각액(월 감가상각액·월 상각액), 비고(Remark) |
| 전산용역비 | `전산용역` · `용역` | 항목명 / 총 금액 / 기간(계약기간 — `감가상각 기간`이라고 적혀 있어도 계약기간으로 해석) | 비고, 차기계약금액(예상계약금액) |

**기간 입력 형식** (한 셀에 시작~종료)

```
2024.02~2029.01              월 단위 (무형자산 권장)
2026.04.01~2027.03.31        일 단위 (전산용역 권장)
2026-04-01 ~ 2027-03-31      '-', '/', '년 월 일' 표기도 허용
```

- `TOTAL`, `합계`, `SUB TOTAL`, `GRAND TOTAL` 행은 항목에서 제외하고 **원본 합계 검증**에만 씁니다.
- 최종 TOTAL 행 **아래**에 적힌 항목은 집계하지 않고 DATA CHECK에 경고로 표시합니다.
- 항목명을 `(1년)`, `(3년)`처럼 적으면 해당 주기로 연장을 예상합니다.
- 전산용역비 **비고**에 아래 문구가 있으면 오류(⚠)가 아닌 **집계 제외**로 표시하고 합계에서 뺍니다.
  - `… Project 귀속` (프로젝트 비용으로 처리) → `Project 귀속`
  - `금액 미정` (예: `2028.06.01 계약 예정 (금액 미정)`) → `금액 미정`
  - `일정 미정` (예: `개발 일정 미정`) → `일정 미정`
  - `자동 연장 계약` 등 그 밖의 비고는 표시만 합니다 (연장은 기본 가정).
- 전산용역비 **지출 월** Column(선택)은 상세 팝업의 '월별 지출' 막대에 쓰입니다. 연간 금액(표·그래프)은 계속 계약기간 월할 안분 기준입니다.
  - `매년 4월 1회` → 매 계약 주기의 4월에 계약금액 전액
  - `매월 6,500,000원씩` → 매월 해당 금액 (월 합계가 계약금액과 다르면 DATA CHECK에 표시)
  - `매월 5,500,000원씩 + 매년 28,000,000원씩` → 매월 금액 + 연 1회분 (지급월이 없으면 계약 시작월로 가정)
  - `매월 약 11,000,000원씩` → '약'이 있으면 계약금액을 균등 분할
  - 해석할 수 없는 문구는 월할 안분으로 표시하고 DATA CHECK에 알립니다.
- `차기계약금액` Column을 추가하면 연장 구간에는 그 금액을 사용합니다 (없으면 현재 계약금액과 동일하다고 가정).

## 4. 계산 규칙

| 항목 | 규칙 |
|---|---|
| 총 상각개월 | 시작월·종료월 포함. `2024.02~2029.01` = 60개월 |
| 월 상각액 | Excel 값이 숫자면 우선 사용. 없으면 총 금액 ÷ 총 상각개월. 두 값이 0.1% 넘게 다르면 `데이터 확인 필요` |
| 연도 상각비 | 월 상각액 × 선택 연도와 실제로 겹치는 개월 수 (`2027.10~` → 2027년 3개월) |
| 연장 가정 | 현재 계약 종료 다음 날부터 **동일 주기**로 계속 연장되고, **갱신마다 전년 대비 3~5% 인상**된다고 가정. 인상 금액은 백만원 단위로 딱 떨어지는 금액 중 4%에 가장 가까운 값 (예: 160 → 166 → 173). 3~5% 안에 백만원 단위 금액이 없는 소액 계약은 4% 인상액을 백만원 단위로 반올림. 주기 = ① 항목명/기간의 `N년`·`N개월` 명시 → ② 시작일+N개월−1일=종료일이 성립하는 달력 월 → ③ 실제 일수 |
| 전산용역비 | 각 계약기간(현재 + 연장 가정)의 금액을 기간에 걸쳐 월할 안분해 선택 연도·월에 귀속. 월 환산 = 해당 월 포함 일수 ÷ 그 달 일수. 1년 계약은 매월 계약금액 ÷ 12. 화면에는 합계와 함께 '현재 계약분 + 연장 가정분' 내역을 표시 |
| 금액 단위 | 최대 금액이 100억 미만이면 백만원, 이상이면 억원. 마우스를 올리면 원 단위 표시 |

## 5. Dashboard 배포 방법 (Static Hosting)

빌드 과정이 없습니다. 이 폴더 전체를 정적 호스팅에 올리면 됩니다. 외부 CDN을 쓰지 않으므로 사내망에서도 동작합니다.

### GitHub Pages
1. 이 폴더를 GitHub Repository에 push
2. Repository → Settings → Pages → Source: `Deploy from a branch`, Branch: `main` / `(root)`
3. `https://<계정>.github.io/<repo>/` 로 접속

### Cloudflare Pages / Netlify / Vercel
- 새 프로젝트 → 이 Repository 연결 (또는 폴더 드래그 업로드)
- Build command: 없음, Output directory: `/` (root)

### 사내 웹서버 (IIS · Nginx · Apache)
- 폴더를 웹 루트에 복사. `.xlsx`의 MIME 타입(`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)이 허용되어 있어야 합니다.

## 6. 데이터 오류 확인 방법

KPI 아래 **DATA CHECK** 줄에서 확인합니다. `상세`를 누르면 문제 행 목록이 열리고, 항목을 누르면 해당 행으로 이동합니다.

| 표시 | 의미 | 집계 |
|---|---|---|
| ⚠ 날짜 확인 필요 | 존재하지 않는 날짜(예: `2027.06.31`) · 시작일>종료일. **자동 보정하지 않음** | 제외 |
| ⚠ 금액 확인 필요 | 0원 · 공란 · 숫자 아님 · 비고에 `확인 필요` | 제외 |
| ⚠ 기간 확인 필요 | `매월`, `분기`, `개발완료 후…` 등 날짜로 변환 불가 · 명시 주기와 실제 기간 불일치 | 제외 |
| ⚠ 데이터 확인 필요 | 월 상각액 불일치 · 기간 원문에 부가 조건(예: `(5년간 매월)`) | 포함 (값 확인 권장) |
| ✓/⚠ 원본 TOTAL | Excel TOTAL 행과 항목 합계 비교 | — |

행을 클릭하면 우측 상세 패널에 **원본 Excel 값(셀 주소 포함)**이 그대로 표시됩니다.
Excel 파일이 없거나, Sheet/Column을 찾지 못하거나, 파일이 손상된 경우 화면 상단에 원인이 표시됩니다.

## 7. 관리자 Update 방법

1. Excel 수정 후 저장
2. 배포된 페이지 하단 **관리자 · 새 Excel 반영 전 미리보기**에서 새 파일을 선택 → DATA CHECK 확인
   (이 브라우저에서만 읽으며 서버로 전송·저장되지 않습니다)
3. 문제가 없으면 `current.xlsx`로 이름을 바꿔 `data/`에 교체 → commit/push (또는 서버 폴더에 복사)
4. (선택) 계산 Logic 점검: `node tests/verify.mjs data/current.xlsx`
   — 이 스크립트의 §38 기대값은 최초 예시 Excel 기준이므로, 새 Excel에서는 단위 검증 통과와 출력 요약만 확인하면 됩니다.

웹페이지에서 직접 업로드하는 기능은 두지 않았습니다. 업로드를 허용하려면 관리자 인증 · 서버 저장소 · 접근통제가 필요하며, 브라우저 코드에 Token/Key/Password를 넣는 방식은 안전하지 않습니다.

## 8. Public / Private 운영 시 보안 차이

| | PUBLIC (링크를 아는 누구나) | LOGIN REQUIRED |
|---|---|---|
| 예시 | GitHub Pages(공개 저장소), Netlify/Vercel 기본 | Cloudflare Pages + Cloudflare Access, 사내 웹서버 + SSO/AD 인증, Azure Static Web Apps 인증 |
| 페이지 접근 | URL만 알면 누구나 | 허가된 계정만 |
| **Excel 원본** | `…/data/current.xlsx`를 **누구나 직접 다운로드 가능** | 인증 뒤에서만 |
| 검색 노출 | `noindex` 메타로 억제만 됨 (접근통제 아님) | 차단 |
| 코드 변경 | 없음 | 없음 — 호스팅 계층에서 설정 |

**PUBLIC으로 운영할 때 반드시 확인할 것**
- 대시보드는 Excel을 통째로 내려받아 브라우저에서 읽습니다. **대시보드에 쓰지 않는 Sheet(전표, 견적 등)도 그대로 공개**됩니다. 공개 배포용 `current.xlsx`에는 `감가상각액` · `전산용역비` Sheet만 남기세요.
- GitHub 공개 저장소는 **과거 버전의 Excel도 commit 이력에 남습니다.** 한 번 올린 파일은 교체해도 이력에서 받을 수 있습니다.
- 계약금액 등 사내 자료라면 LOGIN REQUIRED 방식을 권장합니다. 코드는 그대로 두고 호스팅 설정만 바꾸면 됩니다.

적용된 기본 보호: `robots noindex,nofollow`, `referrer no-referrer`, CSP(`default-src 'self'`, 외부 스크립트 없음), Excel 원문은 모두 HTML 이스케이프 후 표시.
